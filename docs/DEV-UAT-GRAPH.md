# Dev and UAT Microsoft 365 Configuration

Better CaptionKeep has exactly three build lanes: `dist/dev`, `dist/uat`, and `dist/prod`. Dev and UAT may receive an ignored local Microsoft Graph overlay for controlled testing. Production and Store packages never receive that overlay.

## Boundary

- The overlay script accepts only `dev` or `uat`.
- Tenant IDs and client IDs must not be committed, printed in release evidence, or embedded in Store ZIPs.
- Dev and UAT have fixed manifest keys, stable extension IDs, and stable redirect URIs.
- Production uses the same customer-owned setup users receive: local configuration in **Administrator connection details** or managed browser policy.
- Microsoft sign-in uses delegated authorization-code flow with PKCE and no client secret.

## Configure Dev or UAT

Set these process environment variables outside the repository:

- `BCK_DEV_UAT_GRAPH_TENANT_ID`
- `BCK_DEV_UAT_GRAPH_CLIENT_ID`

Then build and configure the chosen lane:

```powershell
npm.cmd run build:uat
node scripts/configure-dev-uat-unpacked.mjs uat
```

Use `dev` or `uat` as the final argument. Rebuilding the lane resets `graphRuntimeConfig.js` to its inert source placeholder, so reapply the overlay after the build.

To test production equivalence, build `dist/prod`, load it unpacked, enter the tenant/client IDs through **Administrator connection details**, and complete the same optional-permission and sign-in flow a Store user receives. Production configuration is deliberately never generated by the overlay script.

Register each governed lane redirect once. Normal rebuilds and version upgrades do not change it. Loading another ad hoc folder is unsupported because it can create a different identity.
