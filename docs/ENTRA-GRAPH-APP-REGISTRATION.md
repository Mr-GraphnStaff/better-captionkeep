# Microsoft Entra App Registration for Verified Teams Transcript

Status: **pilot administrator runbook**. Complete these steps only in the controlled test tenant. This runbook does not authorize a production tenant rollout or Store publication.

Applies to the planned [Enterprise Microsoft Graph Transcript Connector](GRAPH-TRANSCRIPT-CONNECTOR.md).

## What this registration does

The Microsoft Entra app registration gives Better CaptionKeep a public identity for interactive, delegated access to Microsoft Graph. An administrator approves the permissions, and an authenticated user explicitly imports a transcript that Microsoft Graph authorizes that user to access.

The extension must not use or contain a client secret, certificate private key, tenant password, application-only credential, or exported refresh token. It uses OAuth 2.0 authorization-code flow with PKCE through Chromium's `chrome.identity.launchWebAuthFlow` API.

## Before creating the registration

Record the following in the pilot change record:

- test tenant name and tenant ID;
- pilot administrator and technical owner;
- pilot user and synthetic meeting organizer;
- Chrome and Edge extension IDs under test;
- the exact redirect URI reported by each installed extension identity; and
- the rollback owner and end date.

The redirect URI is generated by `chrome.identity.getRedirectURL('microsoft')` and has this form:

```text
https://<extension-id>.chromiumapp.org/microsoft
```

Known Store identities produce these expected redirect URIs, but the administrator must compare them with the runtime value before saving the registration:

```text
Chrome: https://nabjdlnkkaonnbnimnmnhjcbigceebml.chromiumapp.org/microsoft
Edge:   https://edefcbdhahfolgkoamkbknjppojpaffk.chromiumapp.org/microsoft
```

An unpacked build normally has a different extension ID. Load the unpacked extension, copy the runtime redirect URI shown by the pilot interface or service-worker diagnostic, and register that exact URI. Do not assume a Store redirect URI will work for an unpacked identity.

## Create the single-tenant application

1. Open the Microsoft Entra admin center.
2. Go to **Identity > Applications > App registrations > New registration**.
3. Use the pilot name `Better CaptionKeep - Graph Transcript Pilot`.
4. Select **Accounts in this organizational directory only**.
5. Leave the initial redirect URI empty and select **Register**.
6. Record the **Application (client) ID** and **Directory (tenant) ID** in the governed pilot record. These identifiers are not passwords, but do not place tenant-specific values in public screenshots or sample files.

## Configure Chromium redirect URIs

1. In the registration, open **Authentication**.
2. Select **Add a platform > Single-page application**.
3. Add the exact `https://<extension-id>.chromiumapp.org/microsoft` URI for each pilot extension identity.
4. Do not add wildcard redirect URIs.
5. Do not enable implicit access-token or ID-token issuance. The connector uses authorization code with PKCE.
6. Do not create a client secret or upload a certificate for the extension.

If Entra rejects the runtime Chromium redirect or the token exchange, stop the pilot and record the exact error. Do not work around the failure with a developer relay, embedded secret, broad redirect, or application permission.

## Add Microsoft Graph delegated permissions

Under **API permissions > Add a permission > Microsoft Graph > Delegated permissions**, add only:

| Permission | Pilot purpose | Consent |
| --- | --- | --- |
| `Calendars.ReadBasic` | Read only the basic event fields needed to show up to five recent Teams meetings: subject, time, organizer flag, and Teams join information | Delegated; least-privileged calendar scope; grant administrator consent for the governed deployment |
| `OnlineMeetings.Read` | Resolve the specific Teams meeting from a user-supplied join URL or meeting ID | Delegated; Microsoft currently marks admin consent as not required |
| `OnlineMeetingTranscript.Read.All` | List and retrieve transcripts for a meeting the signed-in user is permitted to access | Delegated; administrator consent required |

`openid`, `profile`, and `offline_access` are protocol scopes requested during authentication; they are not a reason to add broader Microsoft Graph data permissions.

Do not add `Calendars.Read`, `Calendars.ReadWrite`, application permissions, `OnlineMeetings.Read.All`, recording permissions, mail, files, chat, directory, or user-directory read permissions. `Calendars.ReadBasic` is sufficient for the recent-meeting selector and does not authorize calendar modification.

Select **Grant admin consent** for the test tenant and retain a screenshot or exported permission record that contains no token or transcript data.

## Enable the Teams transcript API control

The Graph permission alone is insufficient. In the Teams admin center:

1. Open **Meetings > Meeting settings**.
2. Under **Transcript API access**, enable Microsoft Graph access for the controlled pilot.
3. Decide whether **Include speaker attribution** is allowed for the pilot.
4. Record the setting, scope, approver, date, and intended rollback.

Where the tenant supports per-app or per-user scoping, restrict the pilot to the test application and test users. Do not represent a global tenant setting as a narrowly scoped control unless the live configuration proves that scope.

## Configure Better CaptionKeep through managed policy

The connector remains hidden and unavailable unless all three managed settings are present and valid:

| Managed setting | Value |
| --- | --- |
| `enableGraphTranscriptImport` | `true` |
| `graphTenantId` | Directory tenant GUID |
| `graphClientId` | Application client GUID |

These values identify the approved tenant and registration. They are not credentials. Do not add them to the normal user-settings export, browser sync storage, public documentation examples, or Store package defaults.

## Pilot validation

Use a scheduled Teams meeting containing invented phrases and no confidential, personal, customer, health, payment, or production information.

1. Confirm Teams transcription is permitted and start transcription in the meeting.
2. End the meeting and wait for the transcript artifact to become available.
3. Open Better CaptionKeep and confirm the Graph connector reports the expected tenant and redirect URI.
4. Select **Connect Microsoft 365** and complete organizational sign-in.
5. Confirm the consent screen names only the intended delegated permissions.
6. Confirm the synthetic meeting appears in the five recent meetings without exposing attendee lists, message bodies, or unrelated calendar fields.
7. Select the meeting, import the official transcript, and confirm it is labeled as a Microsoft Graph source.
8. Confirm current-meeting selection and manual link fallback resolve the same controlled meeting.
9. Confirm the local live-capture source remains separate and unchanged.
10. Verify behavior with speaker attribution enabled and disabled, if both states are approved for testing.
11. Sign out, revoke the enterprise-app session, disable transcript API access, and remove admin consent in separate tests. Each condition must fail closed without deleting already retained source evidence.

Retain status codes, timestamps, extension version and ID, browser version, permission state, hashes, and sanitized response shape. Do not retain access tokens, authorization codes, refresh tokens, cookies, raw diagnostic bodies, or real transcript content in the repository or support record.

## Expected failures

| Condition | Expected result |
| --- | --- |
| Managed configuration absent | Connector is hidden and Graph calls cannot be initiated |
| User not signed in | Import is blocked and interactive connection is offered |
| Admin consent absent | Microsoft denies the requested transcript permission |
| Basic calendar permission absent | Recent meetings fail closed; current-meeting and manual-link selection remain visible |
| Teams Graph transcript access disabled | Graph returns a governed access-denied response |
| Speaker attribution disabled | The attributed representation is rejected or an unattributed representation is used and labeled |
| Meeting has no Teams transcript | No import is created |
| User is not authorized for the meeting | Graph denies or returns no eligible meeting/transcript |
| Token expired or revoked | Refresh or reauthentication is required; the call does not continue anonymously |

## Rollback

1. Set `enableGraphTranscriptImport` to `false` or remove the three managed settings.
2. Revoke user sessions for the enterprise application if required by the test.
3. Remove tenant admin consent from the enterprise application.
4. Disable Teams Graph transcript API access if it was enabled only for the pilot.
5. Delete the pilot app registration after retaining the approved evidence record.
6. Remove the unpacked pilot extension from test profiles.

Deleting the registration or revoking consent prevents future Graph retrieval. It does not delete transcript source artifacts already retained locally under the organization's approved retention decision.
