# Get help with Better CaptionKeep

Start with the [Wiki](https://github.com/Mr-GraphnStaff/better-captionkeep/wiki), [Troubleshooting](https://github.com/Mr-GraphnStaff/better-captionkeep/wiki/Troubleshooting) or [browser-specific setup guide](https://github.com/Mr-GraphnStaff/better-captionkeep/wiki/Browser-Installation-and-Microsoft-365).

- [Ask a question or share feedback](https://github.com/Mr-GraphnStaff/better-captionkeep/issues/new?template=feedback.yml)
- [Report a bug](https://github.com/Mr-GraphnStaff/better-captionkeep/issues/new?template=bug_report.yml)
- [Request a feature](https://github.com/Mr-GraphnStaff/better-captionkeep/issues/new?template=feature_request.yml)
- [Report a translation problem](https://github.com/Mr-GraphnStaff/better-captionkeep/issues/new?template=localization_report.yml)

GitHub requires an account to submit a report. Plain language is enough: tell us what you tried, what happened, the browser/OS and installed extension version if known. For setup problems, identify the stage (download, installation, sign-in, approval, delivery or import). Include the full helper release tag/repair revision if known; its filename alone cannot distinguish 6.0.3-r2. Unknown values are acceptable.

Public issues must not include real meeting content, participant or join information, private organization identifiers, credentials, tokens or raw deployment receipts/logs. Use invented examples and sanitized errors. Search for a matching issue before filing a duplicate. See [the support guide](https://github.com/Mr-GraphnStaff/better-captionkeep/wiki/Support) and [current versions/known limitations](https://github.com/Mr-GraphnStaff/better-captionkeep/wiki/Release-Status).

For sensitive vulnerabilities use [private vulnerability reporting](https://github.com/Mr-GraphnStaff/better-captionkeep/security/advisories/new) and [SECURITY.md](SECURITY.md). Do not post exploit details in a public issue. For a confidential non-security question, ask for a suitable private contact method without posting the sensitive details first.

Support is maintainer-led. Feedback does not promise a delivery date, and no enterprise response-time SLA is advertised. A local fix is distinct from an available update; the issue records the released fix version when one ships.
